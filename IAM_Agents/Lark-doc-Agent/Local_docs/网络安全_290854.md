# 网络安全科普：SQL注入基础详解
---
## 一、基本定义
SQL注入（SQL Injection）是最常见的数据库攻击手段之一，属于代码注入类漏洞。攻击者通过在Web应用的输入参数中插入恶意的SQL语句，在后端服务器未做有效校验的情况下，恶意SQL会被数据库引擎直接执行，从而实现非法获取数据、篡改数据、控制服务器等攻击目的。

SQL注入漏洞长期位列OWASP（开放式Web应用程序安全项目）年度高危漏洞榜单Top3，是企业Web业务防护的核心关注对象。

## 二、核心原理
Web应用的正常数据查询流程为：
1. 用户在前端提交查询参数（如用户名、商品ID等）
2. 后端服务将用户输入的参数拼接到预设的SQL语句中，发送给数据库执行
3. 数据库返回查询结果给后端，再展示给用户

当后端没有对用户输入的参数进行合法性校验、过滤时，攻击者可以输入包含SQL语法的恶意参数，改变原有SQL语句的执行逻辑：
> 正常查询SQL示例：`SELECT * FROM users WHERE username = '用户输入的用户名' AND password = '用户输入的密码'`
> 攻击者输入用户名为`' OR 1=1 --`，拼接后的SQL变为：`SELECT * FROM users WHERE username = '' OR 1=1 --' AND password = 'xxx'`
> 此时`1=1`恒成立，后面的密码校验被注释符`--`忽略，攻击者无需密码即可直接登录管理员账号。

## 三、常见SQL注入类型
| 类型名称       | 特点说明                                                                 |
|----------------|--------------------------------------------------------------------------|
| 显式注入       | 攻击者可以直接在前端页面获取到SQL执行的返回结果，是最容易利用的注入类型 |
| 盲注           | 页面不会返回具体的查询结果，攻击者需要通过页面响应时间、返回内容差异判断SQL执行结果，利用门槛较高 |
| 报错注入       | 利用数据库的报错机制，让错误信息直接返回页面来获取数据                   |
| 堆叠查询注入   | 攻击者可以一次性执行多条SQL语句，危害极高，可直接实现删库、写入后门等操作 |

## 四、典型危害
1. **数据泄露**：非法拖取整个数据库的用户信息、交易数据、企业机密信息等，造成合规风险和经济损失
2. **数据篡改**：恶意修改数据库内容，比如篡改商品价格、修改用户权限、添加恶意管理员账号
3. **服务器控制**：高权限的SQL注入可以直接执行系统命令，获取服务器控制权，植入挖矿程序、勒索病毒等
4. **业务瘫痪**：攻击者可直接执行删除表、删除数据库等操作，导致业务完全中断

## 五、企业级防护方案
1. **输入校验**：所有用户输入参数严格按照业务规则校验，比如手机号只能是11位数字，用户名限制特殊字符范围
2. **预编译SQL**：使用MyBatis、JPA等ORM框架的预编译机制，禁止直接拼接SQL语句，从根源阻断注入风险
3. **权限最小化**：数据库业务账号仅开放必要权限，禁止业务账号拥有删表、执行系统命令等高权限
4. **WAF防护**：部署Web应用防火墙，拦截常见的SQL注入攻击 payload
5. **定期漏洞扫描**：每季度对所有上线业务做SQL注入专项漏洞扫描，及时修复发现的风险点

## 六、典型案例
2019年国内某电商平台存在SQL注入漏洞，攻击者通过漏洞获取了超过1000万条用户手机号、收货地址等隐私信息，最终企业被监管部门罚款500万元，同时承担用户的赔偿责任，品牌声誉受到严重影响。
