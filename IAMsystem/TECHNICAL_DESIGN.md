# IAMsystem 技术方案设计文档

## 一、系统整体架构
### 1.1 架构设计理念
IAMsystem是面向AI Agent生态的身份与访问控制系统，采用微服务模块化设计，实现身份管理、授权认证、审计追溯三大核心能力的解耦，支持水平扩展和独立迭代。

### 1.2 核心模块组成
| 模块名称 | 端口 | 核心职责 |
|---------|------|---------|
| 身份注册模块 | 9002 | 负责用户(User)/访客(Visitor)/机器人(Bot)身份的注册、身份校验、身份生命周期管理 |
| 委托授权模块 | 9001 | 负责Access Token的签发、校验、撤销，权限委托管理，动态/静态双Token模式支持 |
| 审计追溯模块 | 9000 | 负责全链路操作日志记录、异常行为检测、全局黑名单管理、风险操作拦截 |
| 管理后台模块 | 9005 | 提供可视化管理界面，支持违规记录查询、系统配置、权限管理、黑名单操作 |
| 前端静态服务 | 9006 | 托管管理后台前端页面，提供用户友好的操作界面 |

### 1.3 分层架构
```
┌─────────────────┐
│  前端展示层     │  管理后台页面、Agent SDK接入层
├─────────────────┤
│  API网关层      │  统一入口、流量控制、负载均衡（可扩展）
├─────────────────┤
│  业务服务层     │  身份注册、委托授权、审计追溯三大核心服务
├─────────────────┤
│  数据存储层     │  JSON文件存储（轻量部署）/ 可扩展支持MySQL/Redis
└─────────────────┘
```

## 二、Access Token 设计
### 2.1 Token类型
系统支持两种类型的Access Token，可通过全局配置灵活切换：
| Token类型 | 特点 | 适用场景 | 有效期范围 | IP校验 |
|----------|------|----------|------------|--------|
| 动态Token | 安全级别高，与申请IP绑定 | 普通用户、临时访问场景 | 5分钟~24小时 | 是 |
| 静态Token | 灵活性高，不绑定IP | 服务间调用、AI Agent长期访问场景 | 1小时~1年 | 否 |

### 2.2 JWT Payload结构
Token采用JWT标准格式，Payload包含以下字段：
```json
{
  "jti": "唯一Token标识",
  "AgentID": "申请者Agent唯一ID",
  "scope": "授权的权限范围，JSON对象",
  "delegated_chain": "委托链数组，多层委托场景使用",
  "ip": "申请时的IP地址（动态Token存储实际IP，静态Token存储0.0.0.0）",
  "purpose": "Token用途说明",
  "type": "Token类型：dynamic/static",
  "iat": "签发时间戳",
  "exp": "过期时间戳"
}
```

### 2.3 Token安全设计
1. **加密算法**：采用HS256算法签名，密钥可配置
2. **黑名单机制**：撤销的Token会加入黑名单，校验时优先检查黑名单
3. **权限最小化**：签发时自动计算申请权限与Agent自身权限的交集，避免过度授权
4. **Visitor权限限制**：访客身份只能申请和拥有`online`相关权限，严格限制访问范围
5. **全局配置**：支持全局强制Token类型，自定义有效期限制

## 三、A2A (Agent to Agent) 认证流程
### 3.1 标准A2A调用流程
```
┌───────┐          ┌─────────────┐          ┌─────────────┐          ┌───────┐
│ Agent A│          │ 委托授权模块 │          │ 审计追溯模块 │          │ Agent B│
└───┬───┘          └──────┬──────┘          └──────┬──────┘          └───┬───┘
    │ 1. 申请AccessToken │                          │                     │
    ├───────────────────>│                          │                     │
    │                    │ 2. 身份+权限校验         │                     │
    │                    ├─────────────────────────>│                     │
    │                    │ 3. 审计校验通过          │                     │
    │                    <──────────────────────────┤                     │
    │ 4. 返回AccessToken│                          │                     │
    <───────────────────┤                          │                     │
    │                    │                          │                     │
    │ 5. 携带Token调用Agent B接口 │                 │                     │
    ├────────────────────────────────────────────────────────────────────>│
    │                    │                          │                     │ 6. 调用授权模块校验Token
    │                    │                          │                     ├──────────>│
    │                    │ 7. 校验Token合法性+权限   │                     │           │
    │                    ├─────────────────────────>│                     │           │
    │                    │ 8. 审计校验通过          │                     │           │
    │                    <──────────────────────────┤                     │           │
    │                    │ 9. 返回校验结果          │                     │           │
    │                    <─────────────────────────────────────────────────┤           │
    │                    │                          │                     │ 10. 执行业务逻辑返回结果
    <─────────────────────────────────────────────────────────────────────┤
┌───┴───┐          ┌──────┴──────┐          ┌──────┴──────┐          ┌───┴───┐
│ Agent A│          │ 委托授权模块 │          │ 审计追溯模块 │          │ Agent B│
└───────┘          └─────────────┘          └─────────────┘          └───────┘
```

### 3.2 多层委托流程
支持多级Agent权限委托，委托链会被记录在Token中，校验时会与所有上层权限取交集，确保权限不会被放大：
1. Agent A申请Token，携带委托链：`[]`
2. Agent A使用自己的Token为Agent B申请Token，委托链变为：`[{"AgentID": "A", "scope": "..."}]`
3. Agent B使用Token为Agent C申请Token，委托链变为：`[{"AgentID": "A", "scope": "..."}, {"AgentID": "B", "scope": "..."}]`
4. 校验时最终权限 = 所有委托链权限 ∩ Token自身权限

## 四、API接口定义
### 4.1 身份注册模块（端口9002，前缀/IAMsystem/identity）
#### 4.1.1 用户注册
- 接口：`POST /register/user`
- 请求参数：
  ```json
  {
    "Agent_name": "用户名称",
    "subtype": "user/visitor",
    "scope": {"permission1": true, "permission2": ["read", "write"]},
    "ip": "127.0.0.1"
  }
  ```
- 响应：返回agent_id和明文agent_secret

#### 4.1.2 Bot注册
- 接口：`POST /register/bot`
- 请求参数：
  ```json
  {
    "Bot_name": "机器人名称",
    "Bot_id": "可选自定义BotID",
    "scope": {"permission1": true},
    "sub_scope": {"user": {"p1": true}, "visitor": {"online": true}},
    "api_endpoint": "Bot服务地址"
  }
  ```

#### 4.1.3 身份校验
- 接口：`POST /verify`
- 请求参数：
  ```json
  {
    "agent_id": "AgentID",
    "agent_secret": "Agent密钥"
  }
  ```
- 响应：返回是否有效及对应权限

---

### 4.2 委托授权模块（端口9001，前缀/IAMsystem/auth）
#### 4.2.1 申请Token
- 接口：`POST /apply-token`
- 请求参数：
  ```json
  {
    "agent_id": "AgentID",
    "agent_secret": "Agent密钥",
    "delegated_chain": [],
    "applied_scope": {"p1": true},
    "purpose": "调用XX服务",
    "ttl": 3600,
    "token_type": "dynamic/static"
  }
  ```

#### 4.2.2 校验Token
- 接口：`POST /verify-token`
- 请求参数：
  ```json
  {
    "bot_id": "调用方BotID",
    "agent_secret": "Bot密钥",
    "access_token": "待校验Token",
    "required_scope": {"p1": true}
  }
  ```

#### 4.2.3 撤销Token
- 接口：`POST /revoke-token`
- 请求参数：
  ```json
  {
    "agent_id": "申请者AgentID",
    "agent_secret": "Agent密钥",
    "access_token": "待撤销Token",
    "revoke_reason": "不再使用"
  }
  ```

---

### 4.3 审计追溯模块（端口9000，前缀/IAMsystem/audit）
#### 4.3.1 上报审计日志
- 接口：`POST /log`
- 请求参数：包含操作类型、AgentID、操作详情、IP等字段

#### 4.3.2 异常检测查询
- 接口：`GET /anomaly/detect`
- 支持按时间范围、AgentID、风险等级查询异常行为

#### 4.3.3 黑名单操作
- 接口：`POST /blacklist/add` / `POST /blacklist/remove`
- 支持对AgentID、IP进行黑名单管理
