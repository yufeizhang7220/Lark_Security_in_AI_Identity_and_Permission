# 委托授权模块测试案例
## 📌 测试前置准备
### 1. 环境要求
- 委托授权服务已启动，正常运行在 `http://localhost:9001`
- 审计接口可正常访问（或临时修改代码关闭审计校验，默认审计接口不可用时放行）
- Storage目录下已有测试数据：
  - 测试Agent1：`agent_id = "bot_doc_001"`, `agent_secret = "test_secret_123"`（权限：`{"doc": ["read", "write"], "indata": ["read_bitable"]}`）
  - 测试Agent2：`agent_id = "bot_data_001"`, `agent_secret = "test_secret_456"`（权限：`{"indata": ["read_contact", "read_calendar", "read_bitable"]}`）
### 2. 公共配置
```bash
BASE_URL="http://localhost:9001/IAMsystem/auth"
```

## 📋 接口1：申请AccessToken（/apply-token）
### ✅ 正常场景测试
| 测试用例ID | 测试场景 | 测试步骤 | 请求参数 | 预期结果 |
|-----------|---------|---------|---------|---------|
| APPLY-001 | 正常申请动态Token | 用合法的agent_id和agent_secret申请权限范围内的Token | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "applied_scope": {"doc": ["write"], "indata": ["read_bitable"]}, "purpose": "测试申请Token", "ttl": 3600, "token_type": "dynamic" } ``` | 返回200，包含access_token、expire_at（当前时间+3600秒）、granted_scope和申请的一致 |
| APPLY-002 | 正常申请静态Token | 申请静态类型Token | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "applied_scope": {"doc": ["read"]}, "purpose": "测试静态Token", "ttl": 0, "token_type": "static" } ``` | 返回200，expire_at为null，Token中的ip为"0.0.0.0" |
| APPLY-003 | 申请部分权限（取交集） | 申请的权限超出Agent自身权限，自动取交集 | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "applied_scope": {"doc": ["write", "delete"], "indata": ["read_bitable", "read_contact"]}, "purpose": "测试权限交集", "ttl": 3600 } ``` | 返回200，granted_scope为`{"doc": ["write"], "indata": ["read_bitable"]}`（自动过滤没有的权限） |
| APPLY-004 | 携带委托链申请 | 传入合法委托链，正确计算权限交集 | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "delegated_chain": [{"agent_id": "user_001", "scope": {"doc": ["write"], "indata": ["read_bitable"]}}], "applied_scope": {"doc": ["write"], "indata": ["read_bitable"]}, "purpose": "测试委托链", "ttl": 3600 } ``` | 返回200，Token中的delegated_chain包含传入的委托信息，权限正确 |
| APPLY-005 | 最长有效期限制 | 申请超过24小时的Token，自动截断为24小时 | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "applied_scope": {"doc": ["read"]}, "purpose": "测试最长有效期", "ttl": 999999 } ``` | 返回200，expire_at为当前时间+86400秒（24小时） |
### ❌ 异常场景测试
| 测试用例ID | 测试场景 | 请求参数 | 预期结果 |
|-----------|---------|---------|---------|
| APPLY-ERR-001 | Agent不存在 | agent_id填不存在的ID | 返回401，提示"Agent不存在或已被禁用" |
| APPLY-ERR-002 | Agent密钥错误 | agent_secret填错误的密钥 | 返回401，提示"Agent密钥错误" |
| APPLY-ERR-003 | 申请的权限完全超出范围 | 申请Agent完全没有的权限 | ```json { "agent_id": "bot_doc_001", "agent_secret": "test_secret_123", "applied_scope": {"online": ["web_search"]}, "purpose": "测试越权申请", "ttl": 3600 } ``` | 返回403，提示"申请的权限超出Agent权限范围" |
| APPLY-ERR-004 | 参数缺失 | 不填必填的applied_scope | 返回400，参数校验错误 |
| APPLY-ERR-005 | Agent已被禁用 | 使用状态为disabled的Agent申请 | 返回401，提示"Agent不存在或已被禁用" |

## 📋 接口2：校验AccessToken（/verify-token）
### ✅ 正常场景测试
| 测试用例ID | 测试场景 | 测试步骤 | 预期结果 |
|-----------|---------|---------|---------|
| VERIFY-001 | 合法Token且权限满足 | 1. 先申请包含`indata:read_bitable`权限的Token<br>2. 用该Token调用校验接口，required_scope为`{"indata": ["read_bitable"]}` | 返回200，valid为true，返回对应的权限范围 |
| VERIFY-002 | 静态Token校验 | 1. 申请静态Token<br>2. 用任意IP调用校验接口 | 返回200，valid为true，不校验IP |
| VERIFY-003 | 拥有all权限校验 | Token拥有`doc:["all"]`权限，校验`doc:["write"]` | 返回200，valid为true |
### ❌ 异常场景测试
| 测试用例ID | 测试场景 | 测试步骤 | 预期结果 |
|-----------|---------|---------|---------|
| VERIFY-ERR-001 | Token过期 | 使用已过期的动态Token调用校验 | 返回401，提示"AccessToken无效或已过期" |
| VERIFY-ERR-002 | Token已被撤销 | 1. 申请Token，拿到jti<br>2. 调用撤销接口撤销该Token<br>3. 用该Token校验 | 返回401，提示"AccessToken已被撤销" |
| VERIFY-ERR-003 | IP不匹配 | 1. 从127.0.0.1申请动态Token<br>2. 用其他IP调用校验接口（测试时可以修改请求头模拟） | 返回403，提示"IP地址不匹配" |
| VERIFY-ERR-004 | 权限不足 | 1. 申请只有`doc:["read"]`权限的Token<br>2. 校验时required_scope填`{"indata": ["read_bitable"]}` | 返回403，提示"权限不足，无法访问该资源" |
| VERIFY-ERR-005 | 伪造Token | 使用随便编造的Token字符串 | 返回401，提示"AccessToken无效或已过期" |
| VERIFY-ERR-006 | 调用方Bot密钥错误 | 校验时bot_secret填错误的密钥 | 返回401，提示"调用方Bot密钥错误" |
| VERIFY-ERR-007 | 调用方Bot不存在 | 校验时bot_id填不存在的ID | 返回401，提示"调用方Bot不存在或已被禁用" |

|-----------|---------|---------|---------|

## 🛠️ 批量测试脚本（curl版）
将以下内容保存为`test.sh`，直接运行即可批量测试核心接口：
```bash
#!/bin/bash
BASE_URL="http://localhost:9001/IAMsystem/auth"
echo "=== 开始测试委托授权模块 ==="
# 1. 测试申请Token
echo -e "\n1. 测试申请Token："
RESP=$(curl -s -X POST "$BASE_URL/apply-token" \
-H "Content-Type: application/json" \
-d '{
  "agent_id": "bot_doc_001",
  "agent_secret": "test_secret_123",
  "applied_scope": {"doc": ["write"], "indata": ["read_bitable"]},
  "purpose": "批量测试",
  "ttl": 3600
}')
echo $RESP | jq .
ACCESS_TOKEN=$(echo $RESP | jq -r '.data.access_token')
# 2. 测试校验Token
echo -e "\n2. 测试校验Token："
curl -s -X POST "$BASE_URL/verify-token" \
-H "Content-Type: application/json" \
-d '{
  "bot_id": "bot_data_001",
  "agent_secret": "test_secret_456",
  "access_token": "'"$ACCESS_TOKEN"'",
  "required_scope": {"indata": ["read_bitable"]}
}' | jq .
# 3. 测试撤销Token
echo -e "\n3. 测试撤销Token："
curl -s -X POST "$BASE_URL/revoke-token" \
-H "Content-Type: application/json" \
-d '{
  "agent_id": "bot_doc_001",
  "agent_secret": "test_secret_123",
  "access_token": "'"$ACCESS_TOKEN"'",
  "revoke_reason": "测试撤销"
}' | jq .
# 4. 测试撤销后的Token校验
echo -e "\n4. 测试撤销后的Token校验："
curl -s -X POST "$BASE_URL/verify-token" \
-H "Content-Type: application/json" \
-d '{
  "bot_id": "bot_data_001",
  "agent_secret": "test_secret_456",
  "access_token": "'"$ACCESS_TOKEN"'",
  "required_scope": {"indata": ["read_bitable"]}
}' | jq .
echo -e "\n=== 测试完成 ==="
```
### 运行说明：
1. 需要安装`jq`工具用于解析JSON
2. 替换测试用的agent_id和agent_secret为实际存在的测试数据
3. 赋予执行权限：`chmod +x test.sh`
4. 运行：`./test.sh`
