在 IAMsystem\Delegated\_Authorization 目录下 完成一个 委托授权API

## 功能

接收用户传来的请求格式，分发AccessToken给用户

授权方式包括两种 静态授权 和 动态授权，要求能在后台自由切换两种授权方式

## API地址

localhost:9000/IAMsystem/Delegated\_Authorization 使用POST

## 输入输出格式

### AccessToken 格式

```json
AccessToken{
    "AgentID":"str Agent的英文名（Agent_indata/Lark-doc-Agent/External-Search-Agent）",
    "Subtype":"str 身份权限（user/visitor/bot）",
    "scope":"dict(str,list(str)) 权限范围",
    "AgentSecret":"str 密钥，用来校验身份",
    "iat":"int 颁发时间戳",
    "exp":"int 过期时间戳",
    "IP":"str 申请IP，在访问过程中不许变",
    "purpose":"口令的目的是什么"
}
```

### 请求格式

```JSON
{
    "AgentID":"str 输入注册在系统的英文名",
    "Subtype":"str 用户的身份 user/visitor/bot",
    "AgentSecret":"str 注册在系统的密钥",
    "purpose":"str 申请 AccessToken 是为了干什么",
    "scope":"list(str) 想要使用什么权限",
    "time":"int 单位 s 希望使用多久"
}
```

### 返回格式

```JSON
{
    "AgentID":"str 申请者",
    "status":"int 状态码,601(正确通过),602(用户未注册),603(权限不足),604(未知原因，请稍后重试)",
    "AccessToken":{"AccessToken 如果未通过,则是空字典"}
}
```

### 权限格式

```
具体格式为: {数据:[操作],数据:[操作],...}
其中数据权限包括:calendar database document online
操作权限有: read write create delete web_search fetch_content analyze_content
特别的 
calendar/database/document : all 代表对某一种数据拥有全部权限（增删查改）
online:all :代表可以进行所有的上网操作
```

## 工作流程

1. 当用户发送请求头的时候,验证其AgentID,Subtype,AgentSecret 是否有在 IAMsystem\Storage\USERS\_table.json（用户表） 记录，如果没有，则返回状态码 602
2. 根据 用户表 的scope 字段内容 判断权限是否合法，如果不合理则返回状态码 603
3. 经过判断，请求合法，则分发AccessToken
4. 其中 AgentSecret 的内容需要重新生成,作为这次AccessToken的密钥，time不能超过86400，超过一律按临界值处理
5. 如果是静态授权 IP 为 0.0.0.0 ，exp 则为 -1&#x20;
6. 如果是动态授权 ip即为申请token的地址，exp = 现在的时间 + time 的时间戳
7. 最后将组装完整的 AccessToken 添加存储在 IAMsystem\Storage\TOKENS\_table.json （Tokens表）
8. 最后返回正确的返回json

以这种格式 写入 IAMsystem\Logs\Delegated\_Authorization\_Log\AccessToken\_Auth.log 中

### \[时间] \[AgentID] \[Subtype] 在 \[ip] 申请 \[scopen] 有效期到 \[截止时间] 目的是 \[purpose] 结果是 \[status] 原因是 \[status说明 正确通过/用户未注册......]
