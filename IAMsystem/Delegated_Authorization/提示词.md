## 各种json格式

### 1. AccessToken格式

```JSON
{
 "iss": "IAM-System",
 "AgentID": "AgentID",
 "iat": 1745800000,
 "exp": 1745803600,
 "jti": "唯一TokenID",
 "delegated_chain": [
  {"agent_id": "UserID","jti":"tokenID","scope": {"doc": ["read", "write"], "indata": ["read_bitable"]}},
  {"agent_id": "DocAgent","jti":"tokenID", "scope": {"doc": ["write"], "indata": ["read_bitable"]}}
 ],
 "scope": {
  "doc": ["write"],
  "indata": ["read_bitable"],
  "online": []
 },
 "ip": "127.0.0.1",
 "purpose": "生成一季度销售报告"
}
```

字段说明：

- `delegated_chain`：信任链，按调用顺序排列，最上层是原始用户，下层权限不能超出上层权限
- `scope`：当前Token的有效权限集合，是所有上层权限的交集
- `ip`：绑定请求IP，IP变化则Token失效,如果是 0.0.0.0 则说明任何ip均可登录
- `exp`：Token过期时间，最长不超过24小时，如果是null说明无过期时间，

### 2. scope 权限声明结构

采用"资源类型:操作列表"的键值对结构：

```json
{
  "doc": ["read", "write", "delete"],
  "indata": ["read_contact", "read_calendar", "read_bitable"],
  "online": ["web_search","fetch_content","analyze_content"],
  "iam": ["apply_token", "verify_token"]
}
```

预定义资源类型：

- `doc`：飞书文档操作权限
- `indata`：企业内部数据访问权限
- `online`：外部网络访问权限
- `iam`：IAM系统自身操作权限

### 3. 用户请求json格式

#### 3.1 申请AccessToken

**接口地址**：`POST /auth/apply-token`
**请求参数**：

```json
{
  "agent_id": "",
  "agent_secret": "",
  "delegated_chain": [],
  "applied_scope": {"doc": ["write"], "indata": ["read"]},
  "purpose": "生成销售报告",
  "ttl": 3600(使用时间)
}
```

**响应数据**：

```json
{
  "access_token": AccessToken object,
  "accesstoken_type": "dynamic/static",
  "expire_at": 1745803600(如果是null则说明没有返回时间),
  "granted_scope": {}
}
```

#### 3.2 校验AccessToken

**接口地址**：`POST /auth/verify-token`
**请求参数**：

```JSON
{
    "bot_id":"",
    "agent_secret":"",
    "access_token": "", 
    "required_scope": {"indata": ["read"]}
}

```

**响应数据**：

```json
{
    "valid": true,
    "accesstoken_type":"dynamic/statuc",
    "scope": {"indata": ["read"]}
}
```

#### 3.4 撤销AccessToken

**接口地址**：`POST /auth/revvoke-token`
**请求参数**：

```json
{
    "agent_id": "",
    "agent_secret": "",
    "jti": "唯一TokenID",
    "revoke_reason": "主动撤销"
}
```

**响应数据**：

```json
{
    "valid": true,
    "revoked_at": 1745802000,
    "revoked_by": "user_001",
    "revoke_reason": "主动撤销"
}
```

## API相关

### IAM系统API接口规范

所有接口统一前缀：`http://localhost:9000/IAMsystem`

统一响应格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

统一错误码：

- 200：成功
- 400：请求参数错误
- 401：身份验证失败
- 403：权限不足
- 404：资源不存在
- 500：服务器内部错误

### 申请AccessToken相关API

api地址：`POST /auth/apply-token`

### 验证AccessToken相关API

api地址：`POST /auth/verify-token`

### 撤销AccessToken相关API

api地址：`POST /auth/revoke-token`

## 运行逻辑

### 申请 AccessToken 

1. 从 IAMsystem\Storage\users.json 中验证 是否存在 该agent，status是否是active
2. 根据 委托授权模式 （动态/静态）分配 accesstoken
3. 如果是 动态 dynamic 存在截止时间，ip限定
4. 如果是 静态 static 不存在截止时间，ip=0.0.0.0
5. 权限则是取 申请权限，用户权限 的交集
6. 如果申请通过，将该操作交给 审计 判断是否通过
7. 如果审计通过，返回响应数据，将该操作写入 日志

### 校验 AccessToken

1. 校验 bot\_id 和 agent\_secret 是否正确
2. 从 IAMsystem\Storage\token\_blacklist.json 中验证 是否存在 该jti
3. 将该jti 的 accesstoken 与 请求中的 accesstoken 进行对比，判断是否一致
4. 如果不存在，返回错误码
5. 如果存在，将该操作交给 审计 判断是否通过
6. 如果审计通过，返回响应数据，将该操作写入 日志
7. 如果审计不通过，返回错误码，将该操作写入 日志

### 撤销 AccessToken

1. 校验 agent\_id 和 agent\_secret 是否正确
2. 从 IAMsystem\Storage\token\_blacklist.json 中验证 是否存在 该jti
3. 判断该jti 是否过期 是否已撤销
4. 判断该jti 是否属于当前agent
5. 如果错误，返回错误信息
6. 如果存在，将该操作交给 审计 判断是否通过
7. 如果审计通过，返回响应数据，将该操作写入 日志
8. 如果审计不通过，返回错误码，将该操作写入 日志

### 审计相关api

api地址：`POST /audit/audit`
