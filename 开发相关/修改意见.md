## help的响应机制

help应该要有三层结构

1. 第一层先返回所有的工具描述，不详细介绍各个工具自己
2. 第二层让用户选择好需要的工具后，再返回其相关具体api的描述，权限
3. 第三层则是用户选择好需要的api后，返回相关api的请求响应格式

## 请求调用说明

请求应该完成这几件事

1. 查看AccessToken 是否合法
2. 查看 AccessToken 的权限是否能调用该api ，记得检验整条链路的权限
3. 检测 请求报文 是否有违规操作 如提示词突破权限
4. 用标记记录这次请求 比如 SessionID 记录这是哪条链 RequiredID 记录这是哪段对话 LastRequire 记录上段对话
5. 最后发送请求到工具api

## 部分字段内容

### user请求IAM系统应该包含字段

| 字段            | 格式     | 含义                            |
| :------------ | :----- | :---------------------------- |
| task\_type    | str    | 任务类型，是查看工具，查看api，api详情，还是调用工具 |
| query\_bot    | str    | 需要用到什么机器bot                   |
| API\_ID       | str    | 需要用到该机器bot的什么api              |
| AcessToken    | object | 令牌权限                          |
| session\_id   | str    | 用来记录这是哪段链路，如果是一开始则可以为空        |
| last\_require | str    | 用来记录这段链表的这次对话上一次对话id，用来追踪溯源   |
| Agent\_data   | object | 具体的请求格式                       |

此外还可以有什么时间之类的辅助功能字段

### IAM调用bot的字段

| 字段          | 格式  | 含义                                                            |
| :---------- | :-- | :------------------------------------------------------------ |
| session\_id | str | 用来标记这次对话请求的id，如果bot为了完成这次内容，需要继续请求IAM系统。则需要将last\_require填为这个 |

此外还有自己本身的请求体，这里也不多说了

### 其他字段详解

去除字段中的tokenlist，整条链的上下情况应该由系统内部维护，不对外公布

在AccessToken中，

如果ip=0.0.0.0 说明这是可变ip，任何ip均可使用，

exp=-1，说明该令牌不限时间，任何时候都可以使用，exp用的时间戳是秒级时间戳
