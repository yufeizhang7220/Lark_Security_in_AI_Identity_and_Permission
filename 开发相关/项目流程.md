# 2. 项目工作流程

## 2.0 项目要求

目标：做一个管理Agent权限的系统，可以对异常请求做出一定的反馈

## 2.1 项目需要完成的模块

### 2.1.1 各个Agent制作

资源：飞书 OpenAPI 作为 Agent 工具调用的目标资源

1. **飞书文档助手 Agent**：负责理解用户需求，调用其他Agent完成企业数据查询和外部信息检索，并将最终报告写入飞书文档。
2. **企业数据 Agent**：唯一有权通过飞书 OpenAPI 访问飞书通讯录、日历、多维表格数据的 Agent。
3. **外部检索 Agent**：负责从外部公开网站获取信息，**无权访问任何飞书企业内部数据**。

### 2.1.2 身份注册

注册相关的请求返回的json格式自己规定，规定好之后记得告知所有人

#### 2.1.2.1 用户注册

1. 身份 ：正常用户，游客(user/visitor)
2. 操作： 增删查改（read/write）、上网浏览（web\_search/fetch\_content/analyze\_content）
3. 数据： 日历、文档、数据库（calendar/document/database）

细粒度管理：即精确到对某一个数据有什么权限 记作: calendar:read（对日志有读权限）

其中游客只有上网浏览的相关权限，不能对飞书进行操作

正常用户拥有上网浏览的所有权限，包括部分飞书操作

其中飞书的细粒度权限可以让用户登录larkcli,由larkcli的授权确认

#### 2.1.2.2 机器注册

1. API 地址 ：就是调用请求的地址
2. 使用权限 (也是细粒度管理)
3. 请求和输出的json格式

可以对其功能做一些安全检验，但是不一定需要

### 2.1.3 委托授权

#### 2.1.3.1 实现 Agent 静态授权

1. 对注册用户分发AccessToken
   ```json
   AccessToken{
       "AgentID":"Agent的英文名（Agent_indata/Lark-doc-Agent/External-Search-Agent）"，
       "Subtype":"身份权限（user/visitor/bot）",
       "scope":"权限范围",
       "AgentSecret":"密钥，用来校验身份"
   }
   ```

#### 2.1.3.2 实现Agent动态授权

1. 有时效性的AccessToken

   用户每过一段时间必须重新申请
   ```json
   AccessToken{
       "AgentID":"Agent的英文名（Agent_indata/Lark-doc-Agent/External-Search-Agent）"，
       "Subtype":"身份权限（user/visitor/bot）",
       "scope":"权限范围",
       "AgentSecret":"密钥，用来校验身份",
       "iat":"颁发时间戳",
       "exp":"过期时间戳",
       "IP":"申请IP，在访问过程中不许变"
   }
   ```

### 2.1.4 调用请求模块

请求返回头自定，可以参考之前的json格式，但是其中一定要包括AccessToken链表的内容

```json
"TokenList":{
    "AgentID1":{AccessToken},
    "AgentID2":{AccessToken}
    ...
}
越上面代表越在申请的前面
下面的权限不能超出上面的权限
```

1. 检查用户调用请求的AccessToken，是否正确
2. 使用AI检查用户想要执行的操作是否合法，不合法则打回
3. 如果合法，则调用相关操作
4. 需要有一个help，模块告诉用户我们有哪些工具可以使用

合法验证包括：token是否存在，是否过期，AgentID是否匹配，权限是否合理，提示词是否有权限突破，委托链是否合法...
